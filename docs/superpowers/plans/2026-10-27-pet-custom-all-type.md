# 펫 커스텀 타입 ‘전체’ 정합성 계획

## 확인 결과

- 펫 타입을 고르는 사이드 패널은 간식과 펫 커스텀(효과·짝궁·옷장)이다. 간식은 이미 사슴·돼지 선택지를 제거하고 `전체`를 `null`로 저장한다.
- 펫 커스텀에는 `전체` 선택지가 있지만 사슴·돼지도 노출된다. 서버의 `PetCustomTemplate.petType`은 nullable이고 생성·수정 API와 옷장 구매 조건은 `null`을 공용 타입으로 처리한다. 서버 변경은 필요 없다.
- 커스텀 수정 화면의 두 상태(`react-hook-form`, `useCustomForm`)가 DB의 `null`을 곰으로 바꿔 표시한다. 목록 역시 `null`의 라벨을 찾지 못한다.

## 구현

1. 커스텀 선택지를 `전체`와 진화 가능한 8종으로 한정한다. 사슴·돼지 기존 항목은 목록에 원래 타입을 표시하되 수정 시 `전체` 또는 유효 타입으로 재선택해야 저장되도록 검증한다.
2. API의 `null`을 폼의 `전체` 값으로, 저장 시 `전체`를 `null`로 변환한다. 신규 폼 기본값도 `전체`로 한다.
3. 순수 변환·선택지·검증 테스트를 실패부터 작성한다. `pnpm test`, `npx tsc --noEmit`, `pnpm lint`, 프로덕션 빌드로 확인한다.
4. 어드민 `main`에 머지·푸시하고 Vercel 배포 상태를 확인한다. 운영 데이터 생성·수정은 스모크 테스트로 실행하지 않는다.

## 검증 기록

- 실패 테스트에서 사슴·돼지 선택지 잔존, `null` 재편집 변환 및 목록 라벨 누락을 확인한 뒤 수정했다.
- 어드민 `pnpm test` 181개, `npx tsc --noEmit`, `pnpm lint`(오류 0, 기존 경고 34), Webpack 프로덕션 빌드가 통과했다.
- 서버의 커스텀 구매 테스트 8개가 통과했다. 서버는 이미 nullable 타입 저장·조회와 공용 옷장 구매를 처리하므로 서버 코드는 수정하지 않았다.
