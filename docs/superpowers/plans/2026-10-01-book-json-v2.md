# Book JSON v2 + New Cafe24 Export Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Read both the old and the new Cafe24 export, and emit the bindery JSON in the v2 shape: an `options` object, cover dates, and members. Add `recordPackage` end to end.

**Architecture:**
- The parser splits each `상품옵션` cell into options, so one code path reads both export formats.
- A new `recordPackage` field (and the request's `paidQuestionCount`) threads through the existing shapes: parsed order → validation → `/books` request → confirm request → stored batch item.
- `BookExportBooksService` builds the v2 JSON. It adds a members lookup and takes the cover dates from the first and last cards.
- The frontend updates its types, mappers, tables and preview.

**Tech Stack:**
- Backend: NestJS 10, @nestia/core 2.x, Prisma 5 (MySQL), Jest via `yarn jest`.
- Frontend: Next.js pages router, TanStack Query v5, node:test via `pnpm test`.

```ts
function splitOptions(text: string): { key: string; value: string }[] {
  return text
    .split(OPTION_SEPARATOR)
    .filter((part) => part.trim() !== '')
    .map((part) => {
      const index = part.indexOf('=');
      if (index < 0) return { key: part.trim(), value: '' };
      return { key: part.slice(0, index).trim(), value: part.slice(index + 1).trim() };
    });
}

// New export: the count is the option value (질문 개수=30). Old export: the value is prose and the
// count is that row's 수량 (empty for multi-option cells, so a non-numeric new-format value gives null).
function readPaidQuestionCount(option: OrderOption | undefined): number | null {
  if (!option) return null;
  if (DIGITS.test(option.value)) return Number(option.value);
  return DIGITS.test(option.quantity) ? Number(option.quantity) : null;

## Addendum (2026-10-01): several question-count options selected

The live Cafe24 product page has five question-count selectors: `질문 수(30~100)`, `질문 수(101~200)`, … `질문 수(401~500)`. A customer can pick more than one of them.

Decision (user): such an order is **추출 불가** (error) until an admin picks one of the selected values in the result table. The picked value then drives the request's `paidQuestionCount`, the JSON `purchaseQuestionCount` and the stored batch item. The server still re-validates on `/books` and on confirm. The admin-side recompute is only a convenience.

Additional global rules:
- **Question-count options:** an option is a question-count option when its key starts with `질문 개수` or `질문 수`.
- **Value:** the leading integer of the value (`52`, `52개`, `52문항` all give 52). If the value has no leading integer, use that row's `수량`, but only for a single-option (old-format) cell.
- **Candidates:** `paidQuestionCandidates` is the list of unique values found, in order of appearance.
  - `paidQuestionCount` is that single value when there is exactly one.
  - Otherwise `paidQuestionCount` is `null`.
- **Multiple candidates:** two or more candidates add issue `PAID_COUNT_MULTIPLE`.
  - Level: `error`.
  - Message: `질문 수 옵션이 여러 개 선택되었습니다. 고객 확인 후 하나를 골라 주세요.`
- **Request mappings:** in the `/books` and confirm mappings, the candidates are `paidQuestionCount === null ? [] : [paidQuestionCount]`. A request carries at most one chosen value.

function readPaidQuestionCandidates(options: OrderOption[]): number[] {
  const counts = options
    .filter((option) => QUESTION_COUNT_PREFIXES.some((prefix) => option.key.startsWith(prefix)))
    .map(readQuestionCount)
    .filter((count): count is number => count !== null);

import type { BookOrderIssue, BookOrderIssueCode, BookOrderLevel, BookOrderValidation } from '../../../../client/types';

// Mirrors the server's error-level issue codes (backend evaluate-book-order.ts ISSUE_LEVEL). The
// server re-validates on /books and on confirm, so this recompute only drives the table.
const ERROR_CODES: BookOrderIssueCode[] = [
  'SPACE_ID_MISSING',
  'SPACE_NOT_FOUND',
  'RANGE_INVALID',
  'RANGE_SIZE',
  'COVER_COLOR_MISSING',
  'INCONSISTENT_ROWS',
  'NO_ANSWERED_CARDS',
  'PAID_COUNT_MULTIPLE',
];

const PAID_COUNT_MISMATCH: BookOrderIssue = {
  code: 'PAID_COUNT_MISMATCH',
  message: '결제한 질문 수와 질문 범위가 다릅니다.',
};

function rollUpLevel(issues: BookOrderIssue[]): BookOrderLevel {
  if (issues.some((issue) => ERROR_CODES.includes(issue.code))) return 'error';
  return issues.length > 0 ? 'warning' : 'ok';
}

// Applies the admin's pick for an order whose customer selected several question counts.
export function resolvePaidQuestionCount(order: BookOrderValidation, chosen: number): BookOrderValidation {
  const rangeSize = order.startOrder !== null && order.endOrder !== null ? order.endOrder - order.startOrder + 1 : null;
  const kept = order.issues.filter((issue) => issue.code !== 'PAID_COUNT_MULTIPLE' && issue.code !== 'PAID_COUNT_MISMATCH');
  const issues = rangeSize !== null && chosen !== rangeSize ? [...kept, PAID_COUNT_MISMATCH] : kept;
  return { ...order, paidQuestionCount: chosen, issues, level: rollUpLevel(issues) };
}
```
